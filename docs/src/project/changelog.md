# Changelog

All notable changes to the Rad language are documented here.

## [Unreleased]

### Added

- **The Rust host-value boundary is pointer-safe, and causal capture is graph-aware and bounded.** Every floating NaN is canonicalized before NaN boxing, so host-controlled IEEE payloads cannot forge an object tag; tag classification is pure bit inspection and never dereferences a candidate pointer. The raw `Value`, its object accessors, `GcHeap`, raw globals/calls, component rows, merge payloads, replay/wire codecs, and compiler-owned heaps are crate-private. Rust hosts instead exchange owned, pointer-free `FrozenValue` trees or a read-only `ValueHandle<'vm>` tied to one living VM through `import_value`, `call_global`, `export_global`, `component_value`, `resource_value`, and `enqueue_frozen_event`. Causal proposal and candidate capture now rejects cycles, enforces deterministic depth/node/item/encoded-byte limits before detaching data, charges repeated DAG edges under documented tree-expansion semantics, aborts atomically on every rejection, and leaves the same VM reusable. The WASM feature handshake exposes the active limit profile, Soundness runs the external host API under Miri, and deterministic NaN, cycle, deep/wide graph, alias-detachment, fuzz, and public compile-fail tests cover the boundary.

- **Causal artifacts and captured values are sealed against proof and alias laundering.** Mutable `ChunkBuilder` construction data no longer carries a verification certificate; verification produces an immutable `SealedChunk` whose private code, constants, line table, and proof cannot be separated, and returning to construction form always discards the proof. Safe raw host loading accepts immediate constants only, owning-heap ingress is explicitly unsafe, raw ABI `Value` reconstruction is unsafe, and VM shared state is internal so GC-backed constants cannot escape their owner through a safe chunk-reload path. Inside settlements, every true in-place list/bitset/buffer/byte-buffer/iterator mutation is firewalled; causal compiler lowering uses functional replacements and disables global-scratch vectorization; map iterator cursors are rejected in v0; and proposal/candidate capture validates and recursively detaches data graphs before retention. Certificate-mutation regressions cover opcodes, operands, constants, code/line lengths, raw ingress fuzzing, every interior-mutation opcode, functional causal lowering, and nested captured buffers.

- **Causal settlements now have a verified bytecode boundary.** Every chunk is decoded and control-flow verified before execution, with cached proofs rejecting malformed operands, jumps into operands, settlement-region crossings, mismatched CFG joins, nested/unmatched boundaries, and terminal paths inside a settlement. Runtime settlement tokens bind `EndSettlement` to its owner frame/chunk, while one exhaustive opcode/builtin effect firewall blocks direct world/resource writes, globals/captures, events, schedules, I/O/output, RNG, tasks, and native/FFI escape during causal execution. Settlement blocks use frame-local lexical slots even at top level; adversarial malformed-chunk tests and verifier fuzz/property coverage prove rejection leaves the complete observable VM state unchanged and reusable. The Soundness ASAN workflow also runs each codec/merge test filter as an independent Cargo invocation instead of passing multiple positional filters.

- **Experimental RAD Causal Laws (`--experimental-laws`).** RFC-0001 adds transient typed `intent` declarations, read-only `law` producers, one same-module `resolver` per intent, and atomic `settle` transactions. All laws and resolvers read one base snapshot; proposal input is canonicalized independently of producer order; resolvers stage isolated sparse patches with `next`; overlapping `(entity, component)` writes abort instead of becoming last-write-wins. `why()` renders resolver fan-in through every proposal and producing law while retaining exact event ancestry. Replay, fork wire provenance, sandbox write ACLs, the formatter/LSP, semantic fixtures, permutation tests, and `projects/dogfood/causal-laws/` cover the vertical slice. Constraints and resolver ordering are deliberately absent.

- **`pure fn(...)` and `readonly fn(...)` function types — function values now carry a purity rank the checker can trust.** Function types had a single hidden pure bit and no surface syntax for it, which forced the higher-order-laundering fix to demand PURE callbacks everywhere: a readonly higher-order fn could not accept a readonly callback (the type was inexpressible), and `readonly fn apply(f: fn(int) -> int)` promoted its param all the way to pure. Fn types now rank `pure < readonly < impure` (a bare `fn(...)` stays "promises nothing"): the two new type spellings parse anywhere a type does; assignability accepts an argument ranking at most the parameter, so a pure value goes anywhere and a readonly value satisfies readonly/bare parameters; named `pure fn`s/`readonly fn`s used as values, checker-vouched closures, and the readonly read-builtin family (`res`, `get`, `get_resource`, …) carry their real rank; callback-parameter promotion now targets the strongest type the enclosing row can call (readonly rows get readonly callbacks, everything else pure — explicit annotations are left as written); the fn-value call boundary admits pure values anywhere and readonly values wherever the context allows the readonly effect; and the `query_where`/`query_map` gates trust pure/readonly TYPES, so a `readonly fn(entity) -> bool` callback parameter forwards straight into a query predicate. Spec §8.3 documents the ranks, the syntax, and the promotion rule. Regression tests: `readonly_fn_type_annotation_accepts_readonly_callback`, `bare_fn_param_of_readonly_fn_promotes_to_readonly`, `readonly_callback_rejected_where_pure_required`, `pure_fn_cannot_call_readonly_typed_callback`, `readonly_typed_local_flows_into_query_where` in `core/vm/src/checker/tests.rs`.
- **`query_where` and `query_map` share one read-only callback contract, so filtering and mapping by component values work the obvious way.** `query_where`'s predicate was required to be fully *pure*, but the stated rationale — "no writes, IO, or events" — never justified banning reads, and with only pure functions and an entity ID there was almost nothing to filter BY: the builtin's eponymous use, `query_where(Hero, fn(id) { return (get(id, Hero) |> unwrap).level >= 3 })`, was a compile error steering users to the stringly one-field `with_field` or a manual loop (found dogfooding the language cold — the natural first spelling failed). Its sibling `query_map` had the opposite defect: it enforced **nothing**, so a `set` inside the mapper sailed through the checker. Both callbacks now share the **read-only** contract: `get`/`res`/`has`/`lookup`/`peek`-class builtins and declared `readonly fn`s are accepted (safe because both builtins snapshot the matching entity list before the callback runs, so reads observe a stable world — and the runtime always executed reads fine; `query_where`'s limit was purely a checker restriction), while writes, IO, events, `rand_*`, and unverifiable calls are rejected with the call-naming diagnostic ("must be a read-only predicate/mapper"). A read-only `query_where` predicate inside a system run by `simulate()` also passes the separate simulation-purity analysis, since reads are legal there. Regression tests: `query_where_accepts_a_readonly_predicate`, `query_where_accepts_a_named_readonly_fn`, `query_where_still_rejects_a_writing_predicate`, `query_map_accepts_a_readonly_mapper`, `query_map_rejects_a_writing_mapper`, plus the updated diagnostic test in `core/vm/src/checker/tests.rs`, and the end-to-end `query_where_filters_by_component_values_end_to_end`, `query_map_maps_component_values_end_to_end`, `query_where_read_predicate_inside_simulated_system_is_accepted` in `core/vm/src/vm/exec.rs`.
- **`migrate X(old, from_version)` and declared schema versions turn save-generation detection from a shape sniff into a fact.** A component or resource can now carry a version tag — `component Incident v2 { ... }` — which `save_world()` embeds per type in the save's schema section (`["Incident",["sev"],2]`; versionless types stay two-element, so existing programs' saves are byte-identical). A migrate block that declares the optional second parameter receives the **save's** declared version for its type as an int (`0` for versionless saves and for the v1 tagged-tree/wire formats, which predate versions), so multi-generation archives dispatch on `from_version == 1` instead of `contains(old, "sev")` — two generations that happen to share a field set are no longer indistinguishable, and the sniff can no longer silently pick wrong (dogfood feature seq 69 IDEA 03, the deferred item from the persistence cluster). One-parameter `migrate X(old)` blocks are untouched, versioned save or not. The tag is load metadata, not state: re-tagging a component moves neither `world_digest()` (live or fork form) nor state identity across a rolling upgrade — the digest keeps certifying "same state" while the save carries "which generation wrote this". Regression tests: `migrate_receives_the_saves_declared_version`, `versionless_save_migrates_with_from_version_zero`, `one_param_migrate_still_works_with_versioned_save`, `version_tag_does_not_change_world_digest` in `core/vm/src/migration_tests.rs`; grammar + reference updated in `spec.md`/`builtins.md`.
- **`accum` resource parameters and per-call/per-phase `serial` make the two remaining scheduler levers first-class syntax.** (1) `system Hit(h: mut HP, d: accum DamageLog)` declares an **additive reduction**: writable like `mut`, but in a parallel batch each worker's per-field delta against the batch's base snapshot is folded into the base in schedule order — so `d.total = d.total + dmg` aggregates exactly, deterministically (floats included: the fold order is fixed), and two `accum`-writers of the same resource commute and may share a batch, while any plain reader/writer of it still serializes against them. The contract is checked statically: `accum` only on resource parameters, and every field must be `int`/`float` (a str-field resource or an `accum` component is a compile error pointing at the handler idiom). This is the "explicit reduction so the intent is in the AST and the merge is well defined" A1 asked for (dogfood seq 83 IDEA 02) — the read-modify-write is no longer a plain assignment the merge has to guess about. (2) `schedule serial [A, B, C]` runs that one schedule's systems one at a time in topological order (no worker snapshots, no merge) — the per-call spelling of `--serial-schedule` — and `serial phase Line [A, B]` scopes the same intent to a named group: members never share a batch with each other in any schedule that runs them, while unrelated systems still parallelize alongside. Both spellings document intent ("these systems are ordered, do not race them" was previously unsayable) and neither affects explicit `simulate_par`/`simulate_many`. Regression tests: `accum_writers_of_same_resource_share_a_batch`, `accum_writer_conflicts_with_plain_reader_of_same_resource`, `serial_phase_members_never_share_a_batch` in `core/vm/src/vm/parallel.rs`; `accum_resource_folds_parallel_contributions`, `schedule_serial_keyword_runs_and_matches_parallel_result`, `serial_phase_members_run_in_separate_batches_and_stay_correct` in `core/vm/src/vm/exec.rs`; `accum_param_must_be_a_resource`, `accum_resource_fields_must_be_numeric` in `core/vm/src/checker/tests.rs`; parser tests for both `serial` spellings in `core/vm/src/parser/tests.rs`.
- **`fork_seed()`, `simulate_seeded()`, and an inline override list on `simulate_par` finish the speculative-search surface.** The seeds were write-only: `simulate_par` derives each rollout's rng seed from `(seed, index)`, but no builtin answered "which seed produced THIS result fork", so when rollout 4 of 6 was the outlier that decided a candidate's worst-case score, the only way to re-examine it was to re-run all six (dogfood seq 150, the flagged follow-on). Every `simulate_par`/`simulate_many` result now carries its effective rollout seed: `fork_seed(f) -> int` reads it (`0` for anything that is not a rollout result — derived seeds are never 0 thanks to the SplitMix64 zero-clamp — and `fork_with` clears it, since an overridden copy is a new candidate, not a rollout's output; the seed is local debug metadata, never serialized, never in a digest). The consumer that makes it actionable is `simulate_seeded(fork, systems, ticks, raw_seed) -> world_fork`: ONE rollout under an **exact** seed, no per-index derivation — feed it `fork_seed(outs[i])` and it reproduces that single future bit-identically at one rollout's cost (feeding the derived seed back into `simulate_par(…, 1, s)` would re-derive and produce a different future; that asymmetry is why the pair ships together). It joins the simulate family for static-schedule and lenient-purity rules. And `simulate_par` gained an optional 6th argument — a list of resource values applied to the base fork before the rollouts (`simulate_par(root, S, t, n, seed, [Policy { tax: 8 }])`, same validation as `fork_with`) — so seeding a candidate for a Monte-Carlo sweep needs no `commit()` and no separate fork_with dance. Regression tests: `fork_seed_identifies_rollouts_and_simulate_seeded_reproduces_one`, `simulate_par_override_list_seeds_candidates_without_commit` in `core/vm/src/sandbox.rs`; documented in `builtins.md` with a worked reproduce-one-rollout example.
- **`rad run --serial-schedule` forces schedules to run one system at a time, giving speculation/ECS programs a lever over the implicit parallel scheduler.** `schedule`/phases partition their systems into parallel batches automatically, which is unsteerable: the only way to make a multi-system tick strictly ordered was to split it into one `schedule [X]` call per system — defeating `phase`, whose whole job is to group systems (dogfood feature seq 83). The new flag runs every scheduled system serially in topological order (no worker snapshots, no merge), which is (1) a one-command differential test — flip the flag and compare against the parallel path to see if the scheduler is the culprit, the exact technique used to isolate the seq-74 non-reproducibility bug; (2) a correct-by-construction mode for latency-insensitive, correctness-critical sims; and (3) a way to make `rad run` deterministic regardless of thread count. Explicit `simulate_par`/`simulate_many` are unaffected — the flag steers only the implicit `schedule` parallelism. The guide gained a "Where to put shared-state mutation" section (systems mutate their own entities' components; handlers, which are serial by design, mutate shared resources), documenting the aggregation idiom that stays correct independent of scheduler internals. Regression test: `serial_schedule_runs_multi_system_phase_correctly` in `core/vm/src/vm/exec.rs`. (Deferred from this cluster: a per-schedule `serial` keyword and a first-class `accum` reduction for per-entity accumulation — both larger language-surface changes, filed as follow-ons.)
- **`save_world()` now carries a blake3 integrity envelope, and `try_load_world()` makes loading a save handleable instead of fatal.** Persistence integrity depended on which builtin wrote the bytes: `fork_to_bytes` and recorded traces had a blake3 digest and rejected every tampered payload, but `save_world()`'s `.radw` format was `RADWORLD2 {json}` with **no digest** — a small save silently accepted a JSON null in a bool field, a duplicate entity name, an out-of-range int, and wrong-typed values, forcing apps to hand-roll a `world_digest()` receipt chain to get a guarantee the wire codec hands you for free (dogfood feature seq 69). `save_world()` now emits `RADWORLD3 <blake3-of-body> <body>` (or a compressed `RADPACK1` envelope for large saves) — the exact envelope `radpack::seal` already applies to every other tag — and `load_world`/`try_load_world` verify it and refuse a mismatch loudly; digest-less `RADWORLD2` saves and the v1 tagged-tree still load forever. Separately, `load_world(json) -> int` was the only deserialization entry point in the language that aborted the process on bad input (every other boundary — `fork_from_bytes`, `fork_apply`, `merge_forks`, `sandbox_run`, `json_parse` — returns a value); the new `try_load_world(json) -> Result<int, str>` returns `Ok(entities_loaded)` or `Err(message)` and leaves the live world untouched on failure (the load builds a replacement world and swaps it in only on success), so an app can fall back to a prior backup — the established `get`/`require`, `to_int`/`try_int` fail-fast/handle-it pairing. `world_digest()`'s docs now state it is an integrity receipt, not a validity one. Regression tests: `save_world_carries_integrity_digest_and_roundtrips`, `tampered_save_body_is_rejected`, `radworld2_legacy_save_still_loads`, `try_load_world_returns_ok_on_valid_save`, `try_load_world_returns_err_without_aborting_and_preserves_world` in `core/vm/src/migration_tests.rs`. (Deferred from this cluster: a declared per-type schema version handed to `migrate` blocks — it needs a migration-signature change and is filed as a follow-on.)
- **`simulate_many` and `fork_with` make speculative search parallel in the right dimension and free of live-world writes.** `simulate_par(fork, systems, ticks, n, seed)` runs `n` rollouts of *one* fork — right for Monte-Carlo variance, wrong for search, where a beam-search ply wants B×K *distinct* candidate worlds evaluated at once. With only `simulate_par`, the oracle planner had to serialize its candidates in a loop (parallelism stuck on the cheap axis) and, worse, seed each candidate by `commit()`ing a beam node into the **live** world, mutating it, and forking it back — a read-only tree search forced to write to the real world ~20 times per run, leaving a speculative policy stranded if the process died mid-search (dogfood feature seq 150). Two new builtins fix both: `simulate_many(forks, systems, ticks, seed) -> list<world_fork>` takes a *list* of distinct starting forks and runs them in parallel under the same schedule (per-fork seeds derived from `(seed, index)` exactly like `simulate_par`, so results are bit-identical regardless of thread count); and `fork_with(fork, resource_value) -> world_fork` returns a copy of a fork with one resource overridden — seeding a candidate **without** `commit()`, leaving the live world untouched. They compose: `fork_with` builds the B×K seeded candidates off the beam nodes, `simulate_many` evaluates them all at once. `simulate_many` gets the same static-schedule guarantees as the rest of the family (literal or top-level-const system list, purity analysis, unused-system tracking). Regression tests: `fork_with_seeds_a_resource_without_touching_live_world`, `simulate_many_runs_distinct_candidate_forks_in_parallel`, `simulate_many_is_deterministic_regardless_of_order` in `core/vm/src/sandbox.rs`; documented in `builtins.md`/`spec.md`.
- **A top-level immutable system-list binding can now be used as the `simulate`/`simulate_par` schedule argument.** The language already had a `system` type and accepted `list<system>` as an annotation, but every consumer of a schedule demanded an inline list literal — so `let SET = [system::A, system::B]` type-checked and then failed at the call site with "must be a list literal … not a variable" (dogfood feature seq 22). A beam-search planner (oracle) that expands the same system set at every search node had to copy-paste the schedule at each `simulate_par` site and again for the live `schedule` tick, and keep the copies in sync by hand. A reference to a top-level immutable `let` bound to a list literal of `system::…` references now const-folds to that list, so it is accepted exactly where an inline literal is and keeps every static guarantee (purity analysis and unused-system tracking still see the concrete set). Only immutable, top-level, all-`system::…` lists qualify — a `let mut`, a computed value, or a function call is still rejected, now with a diagnostic that suggests binding the schedule at top level. The runtime already accepted a list of system-ref values, so this is a checker change with no bytecode impact. The rejection diagnostics also now name the actual builtin (`simulate_par()` vs. always saying `simulate()`). Regression tests: `top_level_const_system_list_is_accepted_by_simulate`, `mutable_top_level_system_list_is_still_rejected`, `simulate_par_diagnostic_names_the_actual_builtin` in `core/vm/src/checker/tests.rs`.
- **`sandbox_last_output()` and `sandbox_last_fuel()` expose a guest's structured result and fuel spend to an in-language host.** `run_sandbox_guest` always computed both — the guest's last `sandbox_output(v)` and the fuel it consumed — but `sandbox_run` returned only `Result<world_fork, str>` and dropped them, so the data-only *return* channel worked only over `rad sandbox serve` (JSON-RPC), not from a Rad host (dogfood feature seq 62). The only in-language guest→host channels were the world fork itself (forcing a plugin to *write* state just to communicate, defeating least privilege) and unstructured `print` text. The two accessors read the telemetry the calling VM already holds after a `sandbox_run`: `sandbox_last_output()` parses the guest's `sandbox_output(v)` back onto the host heap (`any | nil`, the `sandbox_input` JSON boundary in reverse) and `sandbox_last_fuel()` returns the fuel spent (`int`, the metering signal for billing/rate-limiting). Both reflect the most recent run (nil/0 before the first), recorded on failures too. This is A3's preferred low-disruption option — the accessor pair keeps every existing `match sandbox_run(...) { Ok(f) => … }` intact rather than widening the return type. Regression tests: `sandbox_output_and_fuel_readable_from_host`, `sandbox_last_output_is_nil_when_guest_reports_none`, `sandbox_output_reflects_only_the_most_recent_run` in `core/vm/src/sandbox.rs`; documented in `builtins.md`.
- **Sandbox capability grants gained a `read` dimension — the sandbox now has a confidentiality boundary, not only an integrity one.** Previously a `sandbox_run` grant governed only writes: a guest holding the narrowest `{ "write": ["Reactor"] }` grant could still `get`, `query`, or `save_world()` every other component in the forked world — a vault balance, an API token — and publish it through the allowed `print` channel, while `diff()`/`assert_only_changed()` reported nothing, because a read leaves no trace in world state (dogfood feature-gap seq 61). The grant now takes a `read` key symmetric with `write`: **omitting it grants read of everything, so every existing grant is unchanged**, an explicit list is an allowlist, and an explicit `[]` reads nothing. The ACL is enforced on every world-read path — `get`/`get_resource`/`res`/`require`/`require_all`/`has`/`lookup`/`lookup_all`/`entities(C…)`/`query {…}`/`query_where`/`query_map`/`query_count`/`with_field`/`why`/`why_resource` and read (non-`mut`) system parameters — keyed by component; the whole-world readers that cannot be keyed (`save_world()`, no-arg `world_digest()`, unfiltered `entities()`) require the `"*"` read grant, mirroring how `despawn` requires the `"*"` write grant. Regression tests in `core/vm/src/sandbox.rs` (`targeted_read_outside_grant_denied`, `granted_read_inside_grant_allowed`, `query_and_entities_honor_read_grant`, `bulk_dump_requires_wildcard_read`, `read_system_param_outside_grant_denied`, `read_grant_absent_reads_everything_backcompat`, plus `caps_read_*` parser tests); documented in `builtins.md`.

### Changed

### Fixed

- **Read-honesty, pipeline IO, and the sandbox mask — the remaining classification drift is closed, and a real capability bypass with it.** Three surfaces, one audit. (1) `save_world`, `world_digest`, `schema_digest`, `why`, `why_resource`, and `fork_seed` were ReadECS in `builtin_effect` but absent from `builtin_required_effects`, so a `pure fn` could hide whole-world reads; all six now require `readonly` (unchanged for `readonly fn`s, whose row allows it — dogfood blast-radius audit found no annotated callers). (2) The IO family (`print`, `eprint`, the fs/stdout helpers, `sleep_ms`, `gc_collect`, `log`, `metric`) was missing from `is_impure_builtin` — the one table the pipeline **direct-stage** gate consults — so `x |> print` executed (and a bare `print` passed as a pipeline callback argument) while `x |> set` was rejected; spec §8.4 restricts pipelines to pure/readonly computation, and that is now enforced for IO too (repo audit: zero existing IO direct stages). (3) `builtin_effect` — whose one functional consumer is the sandbox builtin mask — under-approximated `rand_*` (now IO, with an explicit sandbox allow arm, since seeded guest randomness is a supported feature), `flush_events` (now Event), and `require`/`require_all`/`get_entity`/`recent_events` (now ReadECS). Auditing that mask found the real hole: its deny arm named only the ORIGINAL speculation family (`fork`/`simulate`/`simulate_par`/`sandbox_run`/`commit`/`peek`), so the newer ECS-classified members fell through to the allow arm — a guest holding the narrowest grant could call `load_world` with attacker JSON and REPLACE every component wholesale, bypassing the per-component write ACL that gates `set`/`spawn`/`set_resource`, or nest speculation via `simulate_many`/`simulate_seeded`/`fork_with`/`fork_from_bytes`/`fork_apply`/`merge_forks`. The whole family is now denied by name. Regression tests: `pure_fn_cannot_hide_world_reads`, `pipeline_direct_stage_rejects_io_builtins` in `core/vm/src/checker/tests.rs`; `escape_world_replacement_and_nested_speculation_denied`, `guest_rand_still_allowed` in `core/vm/src/sandbox.rs`.
- **The leak lab's regression test is deterministic at any test parallelism.** `push_cycle_memory_is_flat` measured its slope on a process-global allocation counter that was "shared with concurrently running tests" (its own comment), so a full-parallelism run of the grown suite reproducibly inflated `dropped_per_iter` to ~1.7 KB/cycle against a 512 B budget and failed a healthy build — while passing solo and at low thread counts. The counting allocator now keeps per-THREAD counters (const-initialized `Cell` thread-locals, so allocator access cannot itself allocate or recurse; `try_with` tolerates thread-teardown edges). The whole measurement — compile, VM run, VM drop — happens on the measuring thread and the phase bodies are single-threaded, so the slope is immune to every other test in the binary. Verified: the full suite now passes at default parallelism, the exact condition that failed twice in a row before.
- **A `pure fn`/`readonly fn` can no longer run an impure callback — higher-order effect laundering is closed.** `pure fn take(cb: fn() -> any) { return cb() }` accepted `take(do_write)` where `do_write` called `set_resource`, and the write executed at runtime under the pure annotation: fn-type annotations always resolved to impure fn types, assignability therefore allowed any function as the argument, and calling a function *value* (unlike a named fn) performed no effect check at all — a `cb: any` parameter was an equally open route (found by adversarial re-verification of the seq-253 `set_resource` fix; the probe printed the smuggled write). Three rules close it. (1) A fn-typed parameter of an explicitly effect-annotated fn (`pure`/`readonly`/`io`/`ecs`/`event`) is promoted to a **pure fn type**: the callback becomes part of the declared contract — callers must pass a pure function (a `pure fn` or a pure-inferred closure) — and in exchange the body may call it; parameters of unannotated fns are untouched, and inference never promotes. (2) Calling a function value whose type cannot vouch for purity (an impure fn type, or an `any`-typed callee) inside any effect-restricted context is now an effect violation, mirroring the existing named-fn rule that treats unannotated functions as requiring unrestricted effects. (3) Module-qualified calls (`alias.helper(...)`), which previously bypassed the named-fn effect boundary entirely, now route through the callee's `FunctionSig` like any other named call — so a cross-module `readonly fn` stays callable in a readonly context and a cross-module impure fn is rejected in restricted ones instead of sailing through. A purity-only argument mismatch gets a dedicated hint, since `pure fn(int) -> int` vs `fn(int) -> int` otherwise reads like a non-error. Spec §8.3 documents both rules. Regression tests: `pure_fn_callback_param_rejects_impure_argument`, `pure_fn_callback_param_accepts_pure_closure`, `readonly_fn_callback_param_rejects_impure_argument`, `pure_fn_cannot_call_unverifiable_any_value` in `core/vm/src/checker/tests.rs`.
- **The builtin classification tables are parity-complete — no builtin is invisible to any analysis surface.** The seq-253 fix classified `set_resource`; the follow-up table-parity audit found the remaining drift, all closed now. (1) The eleven speculation/persistence writers (`load_world`, `try_load_world`, `fork_with`, `fork_apply`, `fork_from_bytes`, `merge_forks`, `merge_forks_with`, `sandbox_run`, `simulate_par`, `simulate_many`, `simulate_seeded`) were missing from `is_impure_builtin` — the one table the pipeline **direct-stage** gate consults — so `saved |> load_world` executed (a full world replacement as a pipe stage) while `x |> set` was rejected; all eleven are now classified impure there too. (2) `sleep_ms` and `gc_collect` carried IO in `builtin_effect` but were absent from `builtin_required_effects`, so a `readonly fn` could launder an observable delay into trusted contexts (query callbacks, pipelines); both now require `io` at the annotation boundary. (3) `get_resource` appeared in NO classification table — a world read that defaulted to pure, so a `pure fn` could read the world through it. `builtins.md` already documented it as readonly; the docs were right and the checker wasn't. It is now ReadECS everywhere — including the `is_readonly_builtin` allowlist the read-only-callback breach finder consults, so an inline `query_where`/`query_map` callback may read through it exactly like `res()` (without that entry, the new impure `BuiltinSig` alone would have flipped such callbacks from unchecked to over-rejected) — with a real `BuiltinSig`. (3) A resource written with `update(R)`/`set_resource(R, ...)` in a system body — or in a helper fn the body calls — was invisible to conflict analysis, so two provably conflicting systems parallelized and one write was silently lost (`R=1` where 101 is right); the compiler now collects body ECS accesses (checker effects cover helpers) into scheduler-only synthetic signature entries, so they serialize correctly. (4) `despawn(id)` inside a `mut` query loop — the guide's TTL/particle cleanup idiom, three separate doc appearances — crashed with "Cannot set component on non-existent entity" because the end-of-iteration writeback ran unconditionally, even when the body never touched the binding; the writeback now skips targets the body despawned or removed, matching the system-writeback rule. (5) `query { mut X } where cond` type-checked and then died at runtime with "QueryFilter: expected closure or function": the mut-loop lowering pushed the filter chunk id as a bare int constant where the non-mut path builds a fn/closure value; it now packages the filter identically, captures included. A sixth fix landed alongside: a per-entity `mut` resource accumulator in a parallel batch collapsed to one increment because workers recomputed each iteration from the snapshot — the worker's private world now observes its own resource writebacks. Regression tests: `scheduling_tests` (8) in `core/vm/src/vm/exec.rs` and the batcher/wildcard tests (6) in `core/vm/src/vm/parallel.rs`.
- **A `::` path inside an f-string interpolation no longer aborts the parse.** The interpolation lexer took any `:` at brace depth ≤ 1 as the start of a format spec, so the first colon of `Door::Locked` cut the expression at `Door` and swallowed `:Locked)` as the spec — a hard parse error (`Unexpected token InterpolationEnd`) for sum-type variants, state references, and `system::` refs inside the language's most-used output construct, in all three interpolation forms. A `:` immediately followed by another `:` now falls through to normal tokenization as the `::` path separator; a single `:` still starts a spec, so `f"{val(Color::Red):>6}"` keeps its `>6` spec. Regression tests: `lex_fstring_double_colon_path_in_interpolation`, `lex_fstring_format_spec_after_double_colon_path`, `lex_fstring_dollar_interpolation_double_colon` in `core/vm/src/lexer.rs`.

### Added

- **Native ECS resources (`resource` keyword):** First-class global singleton data, replacing the "God Entity" anti-pattern. Declare with `resource ClusterPool { free_workers: 2, finished: 0 }`. Access via `get_resource(Type)` (returns `Option`, readonly) and `set_resource(Type, value)` (mutating). Systems accept resource parameters alongside components: `system AssignWorkers(pool: mut ClusterPool) { ... }`. The `update(ResourceType) { field = expr }` sugar works without an entity. Resources participate in parallel conflict analysis (systems sharing a mutable resource are serialized), fork/simulate/commit snapshots, and GC tracing. The checker enforces: no `spawn(Resource)` or `entities(Resource)`, no `get_resource(Component)` or `set_resource(Component, ...)`, no duplicate resource declarations, no component/resource name collisions, and no `update(Resource)` or `set_resource(Resource, ...)` inside a system that already holds the same resource as a `mut` parameter (prevents writeback-overwrite bugs).
- **List destructuring in closures and for-loops:** Closure parameters and for-loop bindings now support bracket destructuring syntax. `fn([name, phase]) { return name }` unpacks each positional element into a named binding, eliminating `r[0]`/`r[1]` magic-number indexing in pipelines. For-loops support the same pattern: `for [a, b] in rows { ... }`. Features include: multiple destructured params (`fn([a, b], [c, d])`), mixed plain and destructured params (`fn(acc, [k, v])`), underscore discards (`fn([_, mid, _])`), type annotations (`fn([a, b]: (int, str))`), and `mut` propagation (`fn(mut [a, b])`). The checker infers element types from pipeline context and reports arity mismatches. Pipeline vectorization is gracefully disabled for destructured closures.
- **`main() -> nil` tolerates `?` propagation:** The type checker now allows the `?` operator inside `fn main() -> nil` (and `fn main() -> any`). When `?` propagates `Option::None` from within `main`, the program exits cleanly with no error. This removes the friction of choosing between `-> nil` and `-> any` just to use `?` for early-return on missing data.
- **`enumerate(list)` builtin:** Returns a list of `[index, element]` pairs, matching Python's `enumerate()`. Supported in both the Rust VM and the self-hosted C backend. Pipeline-friendly: `items |> enumerate |> map(...)`.
- **Named system phases:** New `phase` declaration groups systems into named execution phases. `phase Physics [Gravity, Collision, Movement]` declares a phase that expands inline when referenced in `schedule [Physics, Render]`. Phases are validated by the checker (unknown system names are errors) and participate in unused-system diagnostics.
- **Typed event fields (C backend):** The self-hosted C backend checker now validates that `emit` statements assign values matching the declared field types of an event. Previously, type annotations on event fields were parsed but not enforced in the C backend.
- **`find(list, fn)` builtin:** Returns `Some(element)` for the first element where `fn` returns truthy, or `None`. Supported in both the Rust VM and C backend.
- **`max_by(list, fn)` / `min_by(list, fn)` builtins:** Return `Some(element)` for the element with the largest/smallest key (as determined by `fn`), or `None` for empty lists. Supported in both the Rust VM and C backend.
- **`update(entity, Component) { field = expr }` syntax sugar:** Reads the current component value, merges the specified field overrides, and writes it back — all in one statement. The entity expression is evaluated exactly once. The checker validates that field names exist and that expression types match the component's declared field types. Supported in both the Rust VM and C backend.
- **Guarded event handlers (`on Event where`/`when`):** Event handlers now support guard expressions: `on Hit(e) where e.amount > 10 { ... }` or `on Hit(e) when e.amount > 10 { ... }`. The guard is desugared to an `if` wrapper at parse time for checking and bytecode. Supported in both the Rust VM and C backend. Combining **`once`** with a guard retires the handler only after the guard passes (see **Fixed** for correct firing vs. older builds).
- **Anonymous entity literal expressions:** `entity { Comp1 { ... }, Comp2 { ... } }` is now a valid expression that spawns an unnamed entity, attaches the listed components, and evaluates to the entity ID. This is the expression-level counterpart to the existing named `entity Name { ... }` declaration. Useful anywhere an entity value is needed inline -- let-bindings, function arguments, return values, and nested inside other entity literals. Supported in both the Rust VM and the self-hosted C backend.
- **Named entity literal expressions:** Entity literals now accept an optional name expression between `entity` and `{`: `entity "player" { Health { hp: 100 } }` or `entity name_var { ... }`. The name can be any expression evaluating to a string — string literals, variables, f-strings, function calls. This replaces the imperative `spawn("name") + set()` pattern with a single declarative expression. Named entity literals are retrievable via `get_entity()`. Supported in both the Rust VM and the self-hosted C backend.
- **Expression components in entity literals:** Entity literal entries can now be arbitrary expressions in addition to traditional `Component { field: value }` initializers. Variables, function calls, and other expressions that evaluate to component values can be used directly: `entity { Name { value: "Hero" }, pos, make_health(100) }`. The parser uses lookahead to disambiguate — `Ident {`, `Ident.`, and `Ident::` are parsed as component initializers; everything else is parsed as an expression. The AST uses a new `ComponentEntry` enum (`Init` or `Expr`) throughout the VM parser, checker, compiler, visitor, linter, and escape analysis.
- **F-string format specifiers:** F-string interpolations now support Python-style format specifiers after a colon: `f"{value:.2f}"`, `f"{n:06d}"`, `f"{x:#x}"`. The full mini-language (`[[fill]align][sign][#][0][width][.precision][type]`) is implemented in both the Rust VM and the self-hosted C backend. Numbers default to right-alignment; strings default to left-alignment — matching Python semantics. Scientific notation output is normalized across backends (`e+04` style).
- **`format_value(value, spec)` builtin:** Formats a single value using a Python-style format specifier string. Called implicitly by f-string format specifiers, and available as a standalone builtin for dynamic formatting. Supported in both the Rust VM and C backend.
- **Triple-quoted f-strings (`f"""..."""`):** Multi-line f-strings where only `${expr}` interpolates. Bare `{` and `}` are literal text, and inner double-quotes do not need escaping — ideal for code generation. Supported in both the Rust VM and the self-hosted compiler.
- **Multi-line single-quoted f-strings:** `f"..."` now allows embedded newlines (previously rejected in the VM lexer). Parity with the self-hosted compiler lexer.
- **Checker: FStringExpr typed as `str`:** The self-hosted checker now correctly infers `FStringExpr` as `str` (was `any`) and type-checks interpolated sub-expressions.
- **C Backend Conformance**: Achieved 100% parity (176/176 tests passing) with the Rust VM. The self-hosted C compiler now accurately reproduces Rust VM semantics including:
  - RNG parity (`xorshift64`).
  - Recursion depth limit (stack overflow detection).
  - ECS system mutability/writeback (`radcomp_locals`).
  - Value semantics & Copy-on-Write (CoW) deep copying.
  - Match exhaustiveness checking and non-exhaustive match runtime fallbacks.
  - Graceful error handling for missing modules.
  - Centralized ECS cleanup during compilation.

### Fixed

- **`gc_collect()` use-after-free on chunk constants:** The backup collector (`collect_cycles`) did not trace bytecode chunk constants as GC roots. String literal fragments compiled into `Chunk.constants` (e.g. f-string parts) could be swept by `gc_collect()`, causing use-after-free and garbled output on subsequent reads. Fixed by adding chunk constant tracing to the root set alongside stack, globals, and captures.
- **Checker rejected heterogeneous map literals:** The type checker emitted a hard error when map literal values did not unify to a single type, despite the language spec and docs specifying that mixed-value maps should widen to `map<str, any>`. Fixed by widening the inferred value type to `any` when unification fails, instead of erroring.
- **`once` handlers with `where` / `when` guards:** Fixed a bug where a guarded one-shot handler could be marked as fired even when the guard was false. The handler is now retired only after an emission where the guard passes and the body executes; nested `flush_events` / handler dispatch restores guard bookkeeping so inner work cannot incorrectly fire an outer guarded `once` handler. (Rust VM: deferred `fired` marking in `dispatch_event` together with compile-time signaling when the guarded then-branch runs.)
- **`update()` double evaluation:** Fixed a bug where the entity expression in `update(expr, Comp) { ... }` was compiled twice (once for `get` and once for `set`), causing side effects to execute twice. The entity expression is now evaluated into a scoped temporary local.
- **`update()` field type validation:** The `update` checker now validates that each field assignment's type matches the component's declared field type, emitting a clear error with type-conversion hints on mismatch.
- **C backend `max_by`/`min_by` incomparable keys:** `rad_compare_keys` in the C runtime now produces a fatal runtime error when comparing values of incomparable types (e.g., `int` vs `bool`), matching the Rust VM's behavior instead of silently returning 0.
- **C parser `update` keyword fragility:** The `update` dispatch in the C backend parser now checks for a following `(` token, making `update` a true contextual keyword. Using `update` as a plain identifier (e.g., `let update = ...`) no longer causes parse errors.
- **Self-hosted compiler type correctness:** Fixed nullable field access patterns in `checker.rad` and `emit_c.rad` that bypassed the VM checker's nil-narrowing. The `entity | nil` fields (`EntityExpr.name`, `CheckerState.scope`) are now assigned to local variables before nil-checking, matching the established codebase idiom and allowing the VM checker to narrow them correctly. `CheckerState.scope` is now correctly annotated as `entity | nil` (was `entity` despite holding nullable values).
- **C backend `variant_of` canonicalization:** The C emitter now deduplicates variant map entries and prefers short names (e.g., `"Kw"`) over fully-qualified names (e.g., `"TokenKind::Kw"`) when both map to the same internal component ID. Previously the C backend's `rad_variant_of` could return qualified names that the self-hosted parser did not recognize, causing infinite error-recovery loops and catastrophic memory exhaustion when compiling large programs.
- **C backend union type annotation handling:** The `LetStmt` runtime type-check in `emit_c.rad` now correctly recognizes `entity | nil` and `nil | entity` (including whitespace-stripped forms) and generates the proper C guard `(var).tag == RV_ENTITY || (var).tag == RV_NIL`. Previously, compacted annotations like `"entitynil"` caused an `Unknown type annotation` runtime error.
- **C backend checker scope guards:** Added nil-checks and `has(entity, Scope)` guards in `checker.rad`'s `pop_scope` and `define_var` before calling `require`, preventing `require() expects entity, got tag 0` crashes when compiling programs with complex scoping (e.g., the compiler compiling itself).
- **C backend newline escape in fn-ref wrappers:** Corrected the `fprintf` format string in `emit_fn_ref_wrapper` to use `chr(92)` for the C `\n` escape inside triple-quoted f-strings, preventing output divergence in arity-mismatch error messages.
- **C backend `rad_ecs_require` diagnostics:** The `require()` runtime error message now includes the component ID alongside the unexpected tag value, making it easier to diagnose tag-mismatch crashes in generated binaries.
- **`rad new` template:** The default scaffold template emitted `run SayHello`, which is not valid syntax. Changed to `schedule [SayHello]` so new projects compile out of the box.
- **`rad play --port 0`:** When the OS assigns a dynamic port (e.g. `--port 0`), the CLI now reads the actual bound port from `TcpListener::local_addr()` and prints the correct URL. Previously it reported `http://localhost:0`.
- **Sum type variant field syntax diagnostic:** The parser now emits a specific error when a user writes `field: Type = default` inside a sum type variant (the component/struct syntax). The message explains that variant fields use `field: default` and suggests removing the type annotation and `=`.

### Changed (static checking)

- **First-class `system` references (phases A–G):** Expression syntax `system::Name` (and `system::a::b::…` paths) with type `system`. The second argument to **`simulate`** must be a **list literal** of **`system::…` references** only (for example `simulate(f, [system::Physics], 1)`); string literals in that list are rejected with a migration diagnostic. At runtime, `simulate` consumes **`system`-typed values** in that list, not raw strings. **`schedule [system::A, …]`** accepts the same syntax; bytecode stores `system` reference constants for `schedule`, matching `simulate`. The self-hosted C emitter lowers `system::…` to `rad_make_str` for `rad_dispatch_system`. The LSP resolves `system::` paths for hover and go-to-definition on declared systems. See [Language Spec](../reference/spec.md) and `core/vm/src/simulate_syntax.rs`.
- **`simulate` analysis:** Static rules for the second argument live in `core/vm/src/simulate_syntax.rs`; the checker uses `Builtin::Simulate` as the canonical callee spelling.
- **Unknown `system::…` names** referenced in a `simulate` schedule are **compile errors** (via system-reference checking; previously some cases surfaced at runtime as `Unknown system '...'`).
- **Unused-system diagnostics:** The checker warns **per system** (`System 'Name' is declared but never run`) when a system is never invoked via `SystemName()`, `schedule [...]`, or a static `simulate(..., [system::Name, ...], ...)` list. ECS flow warnings for programs with type errors are skipped to avoid noisy follow-on diagnostics.

### Changed (VM runtime)

- **Layered memory model:** Per-system `BumpArena` for temporaries (reset between systems); ECS writes (`set` / `spawn` bytecode paths) deep-copy into **persistent** tagged storage; checker rejects function-typed component and struct fields (plain-data rule). Backup `GcHeap` traces **closures/capture cells and chunk constants** on explicit `gc_collect()` (stack, globals, frame captures, bytecode constant pools)—no periodic full-world sweep. See [Memory Model](../reference/memory-model.md).
- **Air-gap isolation:** Strict separation between persistent ECS storage and the execution stack (arena/GC). ECS reads (`get`/`peek`) deep-copy values out of persistent storage into the GC heap; ECS writes (`set`/`spawn`) deep-copy values in. This prevents dangling pointers across fork/commit/despawn boundaries.
- **`ValueColumn` lifecycle management:** `SoAColumn` wraps field vectors in `ValueColumn`, a custom type with `Clone` (retains persistent `Arc<Object>` refcounts) and `Drop` (releases them). This ensures correct reference counting when columns are cloned by `Arc::make_mut` after a fork, or dropped on despawn.
- **`Arc<str>` string optimization:** `Object::Str` now stores `Arc<str>` instead of `String`. String fields crossing the air gap (e.g. `get`/`peek` deep-copying from ECS to stack) pay O(1) per string via `Arc::clone` — no byte-level copy. New strings are allocated as `Arc::from(s)` once.
- **Explicit `GcHeap` per VM:** Heap allocations for non-persistent VM values take `&mut GcHeap` via the allocator trait. The compiler embeds `gc` in `CompileResult`; `VM::load_compile_result` and `load_chunk_with_gc` merge those arenas. Read-only VM state (chunks, system/handler maps, etc.) uses **`Arc`** to share metadata across workers without deep clones.
- **Parallel ECS schedules:** Conflict-free system batches may run in parallel (snapshot per worker); the main thread applies ECS commands and deferred events (values deep-copied into persistent storage; **no** worker `GcHeap` merge). Deferred events are sorted deterministically for the next flush.
- **Native plugins:** `load_plugin(path, merge_into: &mut GcHeap)` merges the FFI scratch heap after `rad_extension_init` into the VM.
- **Embeds:** **`VM::gc_mut()`** for allocating `Value`s from native host code.

### Added
- **Indexed component fields + `lookup()` builtin**: Component fields can be prefixed with the `indexed` keyword to create a runtime hash index for O(1) entity lookup by field value. The new `lookup(ComponentName, field_name, value)` builtin returns `Some(entity_id)` or `None`. Only hashable types (`int`, `float`, `str`, `bool`, `entity`) may be indexed. Indices are maintained automatically on `set()`, `remove()`, and `despawn()`, and participate in copy-on-write fork snapshots.
- **Formalized `readonly` effect level**: New `readonly fn` declaration for functions that perform ECS reads but no mutations or I/O. ECS read builtins (`get`, `has`, `entities`, `query_where`, `query_map`, `query_count`, `with_field`, `peek`, `lookup`) are now classified as `readonly` (previously some were marked `pure`). `readonly` functions are allowed inside pipeline expressions (`|>`), enabling ECS lookups in pipeline stages. The `is_readonly_builtin` helper and `Effect::ReadECS` variant formalize the distinction between ECS reads and writes.
- **`--profile-copies` runtime diagnostics**: New CLI flag `--profile-copies` enables runtime diagnostics for hidden `Arc` deep clones. When a list mutation (`push`, `set`, `extend`) triggers `Arc::make_mut` on a shared backing buffer, the VM emits a diagnostic to stderr with the source line and element count. Helps identify performance bottlenecks from unintended aliasing in hot loops.
- **`unique` binding keyword**: `let unique` provides compile-time single-ownership guarantees. The checker rejects aliasing via assignment (`let y = x`), function arguments, and closure captures, ensuring the value's `Arc` refcount never exceeds 1 and mutations are always in-place. Reassignment to the same name is allowed.
- **Phase 3 WASM reactor (native CLI)**: Optional Cargo feature `native-wasm-phase3` (default in `core/vm/Cargo.toml`) wires wasmtime, `wasm-encoder` stub emission, and a stable host/guest ABI (`core/vm/src/compiler_abi.rs`). After type-checking, `rad build --target wasm <input.rad> <output.wasm>` writes a reactor module (or copies bytes from `RAD_COMPILER_WASM` when that env var is set). For `rad lsp`, set `RAD_WASM_PHASE3=1` or `RAD_COMPILER_WASM` to route **diagnostics** through the wasm reactor (stub returns none until the guest implements checking). Host `vfs_read` resolves paths: in-memory overlay → filesystem → `RAD_VFS_ROOT` or document parent. See [Phase 3 WASM](../reference/wasm-phase3.md).
- **First-Class Speculative Execution (World Forking)**: Fork the entire ECS world, simulate systems in isolation, inspect results, and optionally commit — all as language builtins.
  - `fork()` — snapshot the ECS world via copy-on-write (`Arc`-wrapped columns; cost is O(A) refcount bumps on column handles/maps, actual data cloning deferred to first mutation via `Arc::make_mut`)
  - `simulate(fork, systems, ticks)` — run named systems on the fork for N ticks in isolation; IO, event emission, and `commit()` are statically forbidden inside simulated systems
  - `commit(fork)` — atomically replace the live world with the fork's state; **clears all pending events**
  - `peek(fork, entity, Component)` — read a component from a fork without committing; returns `Option`
  - Static purity checker prevents IO, event, and commit side effects inside `simulate()`
  - `WorldFork` type in the type system with full checker support
  - Nested `simulate()` supported via depth-counting event suppression
  - C backend: `fork()`, `simulate()`, `commit()`, and `peek()` fully supported; `simulate()` implements a generated `strcmp` dynamic dispatcher and provides zero-overhead fast-path unrolling for static system lists
  - Copy-on-Write snapshot architecture: `SoAColumn` fields (wrapped in `ValueColumn`), `Archetype.entities`, `Archetype.entity_row`, and all `World` bookkeeping maps wrapped in `Arc` with `Arc::make_mut` clone-on-write semantics — fork at 10k entities dropped from ~3,500µs to ~7µs (497x speedup); first mutation of a shared column triggers an O(E) `ValueColumn::clone` retain scan
  - Benchmark suite (`benches/bench_fork.rad`, `benches/bench_fork_only.rad`) with results at 100/1,000/10,000 entities
  - 32 conformance tests covering isolation, purity, error recovery, nested simulation, peek, event suppression, and stress scenarios
  - 3 examples: `flagship_speculative_execution.rad`, `ai_move_selection.rad`, `transaction_rollback.rad`
- **Primitive Matching**: `match` now supports direct matching on primitive literals (strings, integers, floats, and booleans). When matching on these open sets, an unconditional wildcard arm (`_ => { ... }`) is required for exhaustiveness. This eliminates the need for long `if/else-if` chains.
- **BitSet type** (`bitset_new`, `bitset_set`, `bitset_has`, `bitset_clear`): O(1) integer membership set backed by a dynamically-growing `uint64_t[]` word array. Uses ~1 bit per index (an 80,000-element set fits in ~10 KB). Replaces O(n) list `contains` for bookmarks, line flags, visited-node tracking, and similar use cases. Now uses strict value semantics with static escape analysis for $O(1)$ in-place mutation of unique bindings.
- **String interning** (C backend): All runtime strings are interned via an FNV-1a hash table (16,384 buckets, chained). String equality short-circuits on pointer identity, duplicate substrings allocate only once, and keyword/map-key comparisons hit the fast path automatically. Transparent to user code.
- **Import aliasing** (`use "path" as name`): Modules can now be imported under an alias and accessed with dot notation (`alias.member`). Aliased declarations are scoped exclusively behind their alias — they do not enter the flat namespace. This prevents name collisions when two modules define identically named `pub` declarations. Private declarations are not accessible from outside the alias, with clear error messages. Internal references within the aliased module (e.g., `Color::Red` inside a function that returns `Color`) work correctly.
- **`is` operator**: Added the `is` operator for checking sum type variants and state machine states (e.g., `x is Ok`, `door is Locked`). This evaluates to a boolean, providing ergonomic variant checking without verbose `match` blocks.
- **`variant_of(val)` builtin**: Added a builtin for reflection that returns the variant name of a sum type or state machine as a string (e.g., `"Ok"`), or `nil` if the value is not a variant.
- **Module Visibility (`pub`)**: Top-level declarations (`fn`, `component`, `struct`, etc.) are now private to their file by default. They must be prefixed with the `pub` keyword to be accessible from other files via `use`.
- **Tuples**: Fully implemented fixed-size, statically typed tuple expressions `(expr1, expr2)` and types `(T1, T2)` at runtime, including indexing, equality, and `len()`.
- **Query Projection (`select`)**: The `query { ... }` expression now supports a `select` clause to project specific components from matched entities (e.g. `query { Health, Position } select Health, Position`), returning a list of components or tuples instead of just entity IDs.
- **Function Spread Operator**: Added the `..` spread operator for function calls (`f(..args)`), which unpacks a tuple into individual arguments at compile time.
- **Strict Module Boundaries**: Declarations marked `pub` (e.g., `pub fn`, `pub component`) now require explicit type annotations, regardless of whether `--strict-types` is enabled. The compiler enforces this during the lowering phase and performs a reachability analysis to ensure public APIs do not leak private types. This ensures public APIs are always strictly typed while allowing fast, inferred iteration inside module bodies.
- **`remove_key(map, key)` builtin**: Added a builtin for map key deletion.
- **Comprehensive I/O, File I/O, HTTP, and TCP Networking**: Added 22 new builtins to support real CLI tools and servers.
  - **Standard I/O**: `eprint`, `write_stdout`, `write_stderr`, `flush_stdout`, `read_stdin_all`
  - **File I/O**: `append_file`, `file_exists`, `remove_file`, `list_dir`, `create_dir`, `remove_dir`, `read_file_bytes`, `write_file_bytes`
  - **HTTP**: `http_post`, `http_post_json`, `http_request` (full control over method, headers, and body)
  - **TCP Networking**: `tcp_connect`, `tcp_listen`, `tcp_accept`, `tcp_read`, `tcp_write`, `tcp_close`
- **String repetition**: The `*` operator now supports string repetition (`str * int` and `int * str`), e.g., `"=" * 40`.
- **Contextual keywords**: The `entity`, `before`, and `after` keywords are now allowed as identifiers in unambiguous contexts, such as variable names or event field names (`let before = 1`).
- **`let Some(x) = expr else { ... }` / `let Ok(x) = expr else { ... }`**: optional-binding sugar for `Option` and `Result`, compiled as a two-arm `match` expression; documented under variable binding in the language spec.
- **Dead Code Detection**: The compiler now performs a reachability analysis pass to detect and warn about unused functions, components, events, and structs.
- **Generic functions** for user-defined declarations: `fn identity<T>(x: T) -> T` with type argument inference at call sites.
- **Type aliases**: `type UserId = int` and parameterized aliases like `type Boxed<T> = list<T>`.
- **Component spread syntax**: `Component { field: value, ..base }` copies unchanged fields from an existing component value — no more retyping every field on `set()`. Type-checked, compiled, and documented in the ECS guide and builtins reference.
- **New string/character builtins**: `chr(int)`, `ord(str)`, `chars(str)`, `to_upper(str)`, `to_lower(str)`
- **New collection builtin**: `values(map)` returns list of map values
- **Heterogeneous map literals**: maps with mixed value types now infer `map<str, any>` instead of producing a type error — `{"name": "Alice", "age": 30}` works naturally
- **`data_pipeline.rad` example**: comprehensive showcase of string utilities, character operations, safe conversions, functional pipelines, and idiomatic `pop` usage
- **New conformance tests**: `string_builtins.rad` (chr, ord, chars, to_upper, to_lower, values), `heterogeneous_maps.rad` (mixed-value map literals and operations)

### Changed
- **VM Optimization (`Op::ListPushLocal`)**: Optimized list mutations (`list << item` and `push(list, item)` for local variables) and pipeline lowering (`|>` chains). The VM now mutates the list directly in its local stack slot instead of pushing and popping the entire list on every iteration, significantly speeding up loops and functional pipelines.
- **C backend (`emit_c.rad`) module graph**: Multi-file compilation order is computed with **Kahn’s algorithm** in **$O(V+E)$** over file entities and `Dependency` edges. The **ready set** is ordered by **lexicographic `FilePath.path`** so merged declarations are **deterministic** across runs. **Duplicate `use` paths** in the same file only create **one** dependency edge per unique resolved path.
- **Rust VM (`rad-vm`) — GC and values**: Heap allocations for `Value` go through an explicit `GcHeap`; compiler output carries `CompileResult.gc`, merged on load. Browser `WasmChunk` uses a scratch heap merged via `VM::load_chunk_with_gc` before `run` so chunk constants stay valid. Added `Value::int` for inline integer range; APIs like `MapKey::to_value` take `&mut GcHeap`.
- **Rust VM — ECS queries**: `World::query(with, without)` supports structural exclusion; bytecode `EcsQuery` carries with/without counts. The compiler hoists simple `!Component` (and `&&`-combined) negations from `where` into `without` when possible. `query` filter execution reuses a single call frame across entity batches.
- **Rust VM — pipeline lowering**: Fused `map` / `filter` / `flat_map` chains compile to vectorized opcodes and a single lowered loop (e.g. `VecBroadcast`, `VecFilter`, `VecSelect` for conditionals); removed the older fused-pipeline opcode path.
- **Rust VM (`rad-vm`)**: Resolved all `clippy` diagnostics with `cargo clippy -- -D warnings` (CI parity), including redundant `.clone()` on `Copy` types (`Value`), idiomatic `HashMap::entry`, `strip_prefix` / `mem::take`, and related lints.
- **Event dispatch (Rust VM)**: `emit` only enqueues events for the next flush; handlers run when `flush_events()` runs or at the end of a `schedule` block (implicit flush). Double-buffered queues replace synchronous re-entrant dispatch, eliminating stack overflows from event chains. Added **`flush_events()`** builtin; C backend exposes a no-op stub for linking only — full semantics require the bytecode VM.
- **Component Memory Layout Optimization**: Refactored `ComponentData` (used for both `component` and `struct` instances) to use a flat `Vec<Value>` with a shared `Rc<Vec<String>>` layout instead of a `HashMap`. This achieves O(1) field access and significantly reduces memory overhead and allocation costs per component instance.
- **`typeof` improvements**: `typeof(val)` now returns the actual user-defined type name for components and sum types (e.g., `"Result"`, `"Position"`) instead of the internal VM tags `"sum_type"` or `"component"`.
- **Map literal type inference**: Heterogeneous map literal values now widen to `any` (inferred as `map<str, any>`) instead of producing a type error, matching documented behavior and fixing arithmetic operations on dynamic map values.
- **Improved diagnostics**:
  - Added a warning for `if` and `while` conditions that evaluate to a constant boolean (e.g., `if true`, `while false`), helping catch dead code and infinite loops.
  - Promoted the warning for ignored list transforms (like `push`) to a compiler error, preventing silent no-ops when discarding the result of pure operations.
  - Refined `let` vs `let mut` immutability error messages to explicitly suggest changing the original binding to `let mut`.
  - Type mismatch errors for `return` statements now point to the exact `return` statement instead of the function declaration.
  - Added a warning for variable shadowing when the new variable has the exact same type as the shadowed variable.
  - Added a warning for unused function parameters (previously only warned on unused `let` bindings).
  - Added a compile-time error for division or modulo by zero with constant operands.
  - Added a specific error for missing return statements when a function declares a non-nil return type but control flow falls off the end of a branch (e.g., an `if` without an `else`).
  - ECS systems now emit a compiler error if they request the same component type multiple times, preventing runtime aliasing bugs.
  - Pipeline purity checks now correctly validate the purity of nested function calls and anonymous closures passed as arguments to higher-order functions like `map` and `filter`.
  - Component spread syntax (`..base`) now correctly validates that the `base` expression is a component value, preventing runtime crashes.
  - Fixed a bug where `any` typed variables would cause a VM panic when used as the base in a component spread or when accessing non-existent fields.
  - Fixed a bug where `match` guards could contain impure expressions (like assignments), allowing side-effects in pattern matching.
  - Fixed a bug where `match` expressions returning different types from different arms would silently fall back to `any` instead of emitting a type error.
  - Fixed a bug where `match` arms destructuring sum type variants could silently omit fields without using the `..` rest operator.
  - Fixed a bug where `match` arms appearing after an unconditional wildcard (`_`) were not flagged as unreachable.
  - Fixed a bug where closures created inside loops would capture the loop variable by reference instead of by value, leading to unexpected behavior.
  - Fixed a bug where an event handler emitting the same event it handles would cause a stack overflow in the VM.
  - Fixed a bug where attempting to access a field on a primitive type (like `int.foo`) would silently compile to `any` and fail at runtime; it now correctly emits a compile-time error.
  - The compiler now treats unreachable code after a diverging statement (`return`, `break`, `continue`) as a hard compile error instead of silently ignoring it.
- **Pipeline Purity Diagnostics**: The compiler now traces the exact call chain when pipeline purity inference fails. Instead of a generic "function is not pure" error, it reports exactly where the purity breach occurred (e.g., `'outer' is not pure because it calls 'middle' which calls 'inner' which calls impure builtin 'print'`) and suggests the exact `pure fn` annotations needed to fix it.
- **Type Display Consistency**: Fixed type display formatting to correctly use `< >` for generics (`list<any>`, `map<str, int>`) instead of `[ ]`, matching the parser's syntax and preventing syntax errors when users copy-paste compiler hints.
- **Function Return Type Inference**: Fixed a bug where functions explicitly annotated with `-> any` would still emit "Inconsistent return types" errors if they returned multiple different types.
- Unannotated function parameters and missing return types now emit non-strict checker warnings (still accepted, still gradual).
- **`pop(list)` now returns just the last element** (same as `pop_last`), matching standard `pop` semantics from Python/JS/Ruby. Use `drop_last(list)` for the remaining list.
- Refactored "cursed" examples (`cursed_rpn.rad`, `cursed_bst.rad`, `cursed_brainfuck.rad`, `cursed_graph.rad`) to use `pop()` + `drop_last()` and the `chr` builtin instead of manual workarounds
- Updated language spec, builtins reference, parity contract, and all affected conformance tests
